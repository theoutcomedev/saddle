# @deepseek-ai/dsh-client-ui-modes

[English](README.md) | 中文

Saddle Web GUI 的工作区布局：让屏幕的形状去适配工作、设备与当下的时刻。一个布局是一份配方，由外壳针对设备真正能做到的事来解算，因此整个能力等于数据加一个应用器——新增一个只需一条目录记录和它的文案，永远不需要在外壳里另开一条代码路径。node 半边是空 apply（用于 roster 行）。

## 叫布局，不叫 mode

产品里已经有 **agent preset**（Standard、Creator……）——那是助手能做什么——会话头部会把它显示成一枚 pill。这里说的是另一件事：助手工作时屏幕的形状。两者都叫「mode」会让同一个头部出现两枚同名 chip、同一个侧边栏出现两行同一个词，因此这个能力在所有用户可见之处都叫 **布局**：侧边栏行、选择器标题、chip、工具，以及会话事件。

## 这个包拥有什么

**布局目录**（`src/client/catalogue.ts`）：九种排布，每一种都是一份外壳规格——每个面在哪里（`column` / `sheet` / `none`）、留多少外壳装饰（`full` / `compact`）、显示哪种输入框（`full` / `minimal` / `none`）、留多少白（`compact` / `comfortable` / `roomy`），以及阅读栏宽。每条记录还会声明哪些设备类别的选择器提供它，因此手机列出的是手机该做的事，而不是一串通用的形容词。像素宽度留在 `ui-layout` 的 columns 里：布局只说形状，像素由外壳决定。

**按设备的记忆**（`src/client/store.ts`）：每个设备类别上次显示的形状分别记着，而且 store 会跟随 `ctx.device`，而不是在加载时只读一次。跟随才能让被缩放的窗口保持诚实——把窗口拖进手机档位时，记忆、选择器列表与外壳排布会因为同一份事实一起切换。

**应用器**（`src/client/apply.ts`）：对 `ctx.layout` 的一次调用（`applyShell`）加上落在根元素上的 `data-workspace-layout`。外壳会针对设备解算这份规格：一个要求面板的布局，遇到无法并排停靠的设备时会把面板作为抽屉打开，而不是把它丢掉。由于不挂载也不卸载，切换会保住草稿、滚动位置和正在运行的任务。

**三个入口**：侧边栏底部、Deployments 与 Scheduled Tasks 旁边的「布局」行——在手机上它位于会话列表抽屉内，那正是该设备放界面元素的地方；会话头部显示当前布局、一键退出的 chip（与侧边栏行使用同一个图形）；以及 agent 自己的工具。

| 布局 | 设备 | 用途 |
| --- | --- | --- |
| `default` | 全部设备 | 外壳本来的形状：会话列表打开，面板可用但收起 |
| `capture` | 手机 | 输入框是主角，会话列表收成一页随时拉出 |
| `read` | 手机 | 输入框收起，正文独占整屏 |
| `focus` | 全部设备 | 收起会话列表，把详情面板放到正文旁边 |
| `zen` | 平板、笔记本、桌面 | 两侧面板全部收起，正文收成适合阅读的一栏 |
| `workbench` | 平板、笔记本、桌面 | 面板常驻在正文旁边，不用每次打开 |
| `counter` | 平板 | 面向他人的形状：界面让给作品，退出需要明确动作 |
| `studio` | 笔记本、桌面 | 紧凑排版，面板放宽，对话退到一边 |
| `wall` | 桌面 | 满屏展示，没有输入框，也没有导航 |

## 设备模型

本包向 `ctx.device`（属于 `ui-layout`）询问人面前的机器是什么——类别、方向、输入方式，以及面板能否并排停靠——自己不从任何宽度推出其中任何一项答案。布局的请求随后由「摆在哪里」来兑现：在无法并排停靠面板的设备上，`details: 'column'` 会把它作为抽屉打开。

## agent 入口

agent 通过调用 `set_workspace_layout` 工具应用布局，该调用会追加由 [`@deepseek-ai/dsh-workspace-modes`](../../interaction/workspace-modes/README.zh.md) 拥有的 `workspace/layout` 事件。宿主把该事件折叠成 `workspaceLayout` 会话投影（`{ layout, at }`），头部 chip 消费它：一条指令按其序号只被应用一次，因此「重新进入一个用户已经退出的布局」依然生效，而「退出」不会被当初进入它的那条指令撤销。用户自己的切换直接写入 store，不经过日志往返。

## Model Experience

间接相关：本包只负责渲染、排布与记忆；模型能做什么——工具名、描述、参数枚举与持久记录——属于 `@deepseek-ai/dsh-workspace-modes`。这里不新增任何模型可见文本。

#### KV Cache effect

本包不产生缓存影响。切换只重排面板与列宽，不触碰系统提示词或工具目录，因此不会让任何请求前缀失效。工具目录由会话的 agent preset 固定——这也正是本插件不随布局增删工具的原因。

## Known Limitations and Deferred Work

- **一次只能一个布局。** 布局不能叠加；Focus 目前还不是其他布局的子状态。
- **记录下来的指令由会话头部消费。** 在未打开的会话中应用的布局，会在该会话被打开时生效。
- **目前只有工作类布局。** Pillar B 目录中的 Play、Share、Morning Briefing、World Builder 以及 Party / Field Capture 尚未构建；Play 与 Share 是接下来的两个，等本包验证过的机制就位后，它们各自就是一条目录记录加一个 slot 贡献。
- **没有按工作区或按会话的覆盖。** 记忆只按设备类别，未做过选择的类别得到默认排布。
- **包名仍叫 `ui-modes`。** 真正要改的是人读到的名字；包名、slot id 与宿主包名保持原样，以免牵动每一条 bundle 行与 tsconfig 引用。
- **chip 的退出没有回执。** 退出布局是一次本地写入，因此排布失败表现为「没有变化」，而不是一条错误；`ctx.layout.applyShell` 只会在根条目尚未接线时抛错，而挂载后的 chip 到不了那种状态。
