# @deepseek-ai/dsh-workspace-modes

[English](README.md) | 中文

workspace 模式的 agent 侧：`set_workspace_layout` 工具、它写入的 `workspace/layout` 持久事件，以及浏览器半边读取的 `workspaceLayout` 会话投影。模式长什么样——哪些面板收起、面板与阅读宽度各是多少——属于 [`@deepseek-ai/dsh-client-ui-modes`](../../client/ui-modes/README.zh.md)；本包只管模型可以请求什么，以及「请求过」这件事的记录。

模式不是 agent 可以持有的设置，而是记录在会话日志里的一次请求，一次调用一个事件。因此该条目的行为可重放，刷新或第二个标签页得到的完全一致；正在看屏幕的人会在工具返回时看到排布改变。

投影把最后一次请求折叠成 `{ layout, at }`，其中 `at` 是记录它的那个事件自身的序号。序号正是这个键存在的理由：针对同一个模式的两条请求是两条指令，仅按值判断的渲染器会忽略第二条——因此「让我回到 zen 模式」在用户已经退出 zen 之后依然生效，而退出也永远不会被当初进入它的那条指令撤销。

## 叫布局，而非 mode

agent preset 是助手能做什么；布局是它工作时屏幕的形状。会话头部两者都会显示，因此本包及其浏览器半边在所有「人或模型能读到」的名字里都用「布局」——工具、参数、它追加的事件，以及客户端折叠的投影。包名（`dsh-workspace-modes`）是旧词唯一残留的地方，因为改名会牵动每一条 bundle 行与 tsconfig 引用，而对读者没有任何好处。

## Model Experience

**工具。** `set_workspace_layout` 接收一个必填的枚举参数，取值来自目录（`standard`、`focus`、`zen`），返回一行文字，说明模式名及其含义。描述会列出每个模式及其用途，且由 `src/catalogue.ts` 派生，因此枚举与文案不会脱节。

**记录状态。** 每次调用写入一个 `workspace/layout` 事件，仅入日志、不进入对话表面：它不属于模型回读的转录内容，模型对「发生了什么」的认知只有工具结果。

#### KV Cache effect

没有影响。工具目录与系统提示词由会话的 agent preset 固定；模式切换只写一个会话事件，不会让任何请求前缀失效。

## Known Limitations and Deferred Work

- **目录是构建期常量。** 部署无法通过配置新增模式；新增意味着在本包与浏览器包的目录各加一条，后者有一个 spec 同时读取两边。
- **没有「退出」工具。** 退出是用户在 chip 上的手势；模型只能通过回到 `standard` 撤销自己的请求。
- **排布本身不在宿主侧验证。** 工具只记录请求；浏览器是否能兑现它从宿主侧不可观测，而未运行的客户端会在下次加载时看到它。
